# 이야기형 그래픽 쇼츠 제작법 (2026.10.18 첫 실험: 붉은 번개 103년)

저장소: github.com/evan-stock/cardnews (main). 인스타 릴스보다 **유튜브 쇼츠용**이다(사용자 판단).
벤치마크: 유튜브 '잘난지'(@잘난지, 구독 2.9만) — 붉은 번개 342만, 침대째 사라진 남자 335만, 노벨상 실험 327만, 모아이 전설 258만. 채널 크기가 아니라 형식이 조회수를 만든다. 분석 문서: 프로젝트 `claude/벤치마킹/잘난지_쇼츠_분석.md`.

## 언제 쓰나
- 신기한 자연·과학·역사 미스터리처럼 '이야기'가 있는 소재. 실제 영상이 1~2개뿐이어도 그래픽으로 이야기를 채울 수 있을 때.
- 반전 구조가 나오는 소재: "다들 헛것이라 했는데 → 결국 증명", "쓸모없어 보였는데 → 알고 보니", "작은 디테일 하나 때문에".
- 단순히 보기만 해도 '와'인 영상(로드스터 같은)은 이 방식 말고 원본 영상 릴스가 낫다.

## 1. 소재·사실 확인
- 기사·위키백과 등 2곳 이상으로 연도·숫자·이름을 확인한다. 확인 못 한 건 빼거나 "~로 알려졌다".
- 다른 채널 제목·대본을 베끼지 않는다. 같은 사실이라도 우리 말로, 다른 각도(예: "찍히기까지 103년")로 쓴다.

## 2. 대본 (6~8장면, 목표 25~30초)
- 1장면: 실제 영상 + 결론을 먼저 던지는 한 문장(주제+결과+숫자). 예: "구름 위에서 터지는 이 '붉은 번개', 사진으로 증명되기까지 103년이 걸렸습니다."
- 가운데: 연도순 반전 흐름 — 첫 목격 → 왜 증거가 없었나(숫자) → 예측했지만 못 찍음 → 우연히 찍힘 → 인정받음.
- 끝 직전: 지금의 실제 장면(가장 멋진 실제 영상·사진).
- 마지막: "이런 뜻밖의 발견, 매일 올립니다. 팔로우(구독)하고 놓치지 마세요."
- 문장은 '~습니다'체, 한 문장 25~40자. 숫자는 글자로 읽히게("50에서 90킬로미터").
- 강조어는 '작은따옴표' → 자막에서 노란색.
- 위 고정 제목(hook.t): 2줄, 줄당 11자 안팎. 1줄 노랑·2줄 흰색, '강조'는 노랑. 예: "증거 없던 '붉은 번개'\n찍히기까지 '103년'". today-worthy-cover-hook의 26가지 템플릿 중 미스터리·반전·숫자형을 쓴다.

## 3. 화면 소재
- 실제 영상: drafts/video.json → fetch-video 워크플로(유튜브는 막힘. 기사 mp4·X·틱톡·VideoPress·직접 mp4/jpg/mp3 주소 가능). 사용자가 올린 파일도 가능.
- 공개 사진: 위키미디어 커먼즈(NASA 등 퍼블릭 도메인, CC0, CC BY-SA). fetch-video에 커먼즈 API 주소(`https://commons.wikimedia.org/w/api.php?action=query&generator=search&gsrnamespace=6&prop=imageinfo&iiprop=url|extmetadata&iiurlwidth=1600&format=json&gsrsearch=검색어`)를 넣으면 api*.json으로 받아 라이선스까지 확인할 수 있다.
- **그래픽은 반드시 움직이게 만든다**(사용자 요청: 정지 그림은 안 됨). 예시 코드 `scripts/story_shorts/anim_sprite_example.py`를 복사해 장면 함수만 바꾼다.
  - 크기 1080x1490(위 검정 띠 430px 아래 영역), 30fps, 7초.
  - 움직임 예: 별 반짝임, 대상이 번쩍 나타났다 사라짐, 사람이 팔을 듦, 숫자 카운터가 0→90 올라감, 비행기 이동, 선(화살표) 그려짐, 물음표 팝업·흔들림, TV 지지직 + REC 깜빡임 + 시간 흐름, 글자 아래서 올라오며 등장.
  - **자막 자리(그래픽 y≈760~1050)는 비운다.** 큰 연도·설명은 그래픽 아래쪽(y≈1070~1350)에 둔다.
  - 그래픽 속 글자는 연도·짧은 설명만. 지어낸 인용문을 넣지 않는다.
  - 실제 기록이 아닌 재현 화면(예: 1989년 TV 속 영상)에는 '재현 그래픽'이라고 작게 표시한다.
  - 폰트: /usr/share/fonts/opentype/noto/NotoSansCJK-Black.ttc (작업공간에 설치돼 있음).
- 실제 영상 전처리: 순간적인 장면은 ffmpeg로 실제 속도 + 8~16배 느리게 이어 붙인 클립을 만들고, 사진처럼 쓰는 장면은 setpts로 늘린다.

## 4. 원고와 제작 (render 전용 통로)
- 원고 파일: `drafts/shorts_tw.json` → 워크플로 `shorts-tw.yml`이 영상만 만든다(업로드 없음). 동물 쇼츠의 `drafts/shorts.json`은 건드리지 않는다(다른 채팅과 충돌).
- 원고 예시:
```json
{"id":"YYYYMMDD-주제","mode":"render",
 "hook":{"t":"증거 없던 '붉은 번개'\n찍히기까지 '103년'"},
 "style":{"mascot":null,"sub_size":84,"title_size":84,"chunk":12,"gap":0.04},
 "speed":1.25,
 "credit":"영상: @원작자 · 사진: NASA",
 "scenes":[
  {"say":"…","video":{"src":"video/flash.mp4","start":0,"x":0.5,"y":0.45}},
  {"say":"…","video":{"src":"video/a1886.mp4","start":0}},
  {"say":"…","img":"cand/iss.jpg","zoom":0.10},
  {"say":"이런 뜻밖의 발견, 매일 올립니다. 구독하고 놓치지 마세요.","img":"cand/final.jpg","zoom":0.05,"end":true}],
 "photo_credits":["@원작자","NASA"],
 "sources":[{"publisher":"","url":"","date":""}]}
```
- 설정 의미: 자막 84·제목 84(기본 116·96은 너무 큼, 사용자 지적), 한 줄 12자, 장면 사이 쉼 0.04초, 전체 1.25배속(목소리 음높이 유지) → 40초가 31초로 줄었다.
- 목소리: 타입캐스트(맥북 로컬 모드). 서버가 state/tts_queue/<id>.json 요청서를 남기면 맥북이 2분마다 만들어 media/<id>/tts/에 올리고, 그 push로 shorts-tw가 다시 돌아 완성된다. 문장(say)을 바꾸면 목소리를 새로 만든다. 문장을 안 바꾸고 화면·속도·글자만 바꾸면 기존 목소리를 그대로 쓴다.
- 맥북이 꺼져 있으면 대기한다. 사용자는 Edge 목소리를 원치 않는다(대체 금지).
- 진행 확인: `git pull` 후 `media/<id>/short.mp4`, 로그 `state/shorts_tw_log.txt`.
- 결과 확인: ffmpeg로 2.5초 간격 프레임 모음을 만들어 직접 보고(글자 겹침·잘림), 사용자에게 mp4를 보낸다.

## 5. 음악
- 내레이션이 주인공이라 배경음악은 작게(0.10~0.16).
- **"Investigations"(Kevin MacLeod, assets/bgm/mystery_investigations.mp3)는 이 형식에 안 어울린다는 사용자 평가 — 쓰지 않는다.** 다른 곡을 고를 때는 후보 2~3곡을 제안하고 사용자에게 고르게 한다.
- 저작권 없는 곡만(유튜브 오디오 보관함, CC0, CC BY는 설명란에 표기: 원고 `bgm_credit`). assets/bgm/README.md에 곡과 라이선스를 기록한다.

## 6. 업로드
- 유튜브 채널을 먼저 사용자에게 확인한다(현재 연결: 동물 쇼츠 채널, 쇼핑 채널). 오늘의쓸모 유튜브 채널이 생기면 config의 shorts.channels와 토큰을 추가한다.
- 업로드는 사용자 승인 후. 설명란에 출처(매체·날짜), 사진·영상 원작자, 음악 표기, '일부 장면은 재현 그래픽' 문구를 넣는다.

## 올리기 전 체크
- 25~35초인가, 첫 2초에 실제 영상 + 결론 문장이 나오나
- 모든 그래픽 장면이 움직이나, 자막과 그래픽 글자가 겹치지 않나
- 연도·숫자를 2곳 이상에서 확인했나, 재현 장면 표시를 했나
- 다른 채널 문구를 그대로 쓰지 않았나
- 출처·원작자·음악 표기가 설명란에 있나
